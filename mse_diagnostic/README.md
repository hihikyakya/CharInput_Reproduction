# 고정 목표 MSE 진단과 원고 집계값 검산

## 실행

Python 3.12와 NumPy가 필요하다. 확인한 버전은 Python 3.12.14, NumPy 2.3.5이다. 네트워크와 GPU는 사용하지 않는다.

```bash
python -m pip install -r requirements.txt
python reproduce.py --out rerun
```

`results/`는 동봉한 기준 실행 결과이다. 생성된 `runs.csv`에는 시드별 결과, `summary.csv`에는 5시드 산술평균과 표본표준편차(ddof=1), `aggregate_audit.json`에는 첨부 원고의 반올림 집계값에서 산출한 지표가 있다. BLAS 및 CPU 차이에 따라 0에 가까운 잔차가 달라질 수 있다. 코드에 포함된 수치 허용오차 기반 검사를 통과하는지 확인한다.

## 새 대조 실험의 설계

- 16개의 토큰을 독립 균등하게 추출한 길이 17의 시퀀스를 사용한다. 각 시드(17, 29, 43, 59, 71)는 독립적인 학습 1,024개, 테스트 256개의 시퀀스를 생성한다. 모든 시퀀스 내부 인접 쌍을 사용하여 각각 16,384개 및 4,096개의 위치를 얻는다. 같은 시드에서 가시성 조건 간에는 같은 데이터와 고정 원-핫 목표를 쓴다.
- 시점 t의 목표는 16차원 고정 벡터 e(xₜ₊₁)이다. 현재 토큰 xₜ만 주는 조건과 xₜ 및 xₜ₊₁를 주는 누출 조건에서 절편을 포함한 선형 최소제곱법으로 학습한다. 각 토큰의 원-핫 벡터에서 마지막 좌표를 제외한 15개를 입력한다. 미래가 보이는 조건은 모델이 다음 토큰을 그대로 복사할 수 있도록 의도한 양성 누출 대조군이다.
- MSE는 테스트 위치와 목표의 모든 좌표에 대한 제곱오차 평균이다. 정규화 MSE(NMSE)는 고정된 **학습** 목표평균으로 예측했을 때의 테스트 MSE로 나눈 값이다. 서로 다른 목표 공간의 원고 집계값 검산에는 별도로 **테스트** 평균 기준을 사용한다.
- t 시점의 토큰을 고정하고 xₜ₊₁를 (xₜ₊₁+1) mod 16으로 바꾼다. `suffix_max_change`는 모든 테스트 위치와 좌표에 걸친 예측 변화 절댓값의 최댓값이다. 현재 토큰만 보는 모델은 예측이 완전히 동일해야 한다. 추가로 모든 목표 벡터의 진폭을 1/4로 바꿔 재학습한 뒤 원시 MSE가 1/16인 반면 NMSE는 같음을 확인한다.
- 독립 토큰이라 인과 예측의 모집단 최적값은 균등 벡터이며 이때 이론상 좌표평균 MSE는 (K−1)/K²=15/256이다. 결과는 미래 입력에 접근할 때 낙관적인 MSE를 얻을 수 있음을 검사한다. 이 실험은 가설을 분리하기 위한 선형 대조군이다. WikiText/LAMBADA 원래 Transformer의 기억 정도나 모델 간 인과적 우위를 측정할 수 없다.

## 기존 실험의 산술 검산

`reported_inputs.json`은 첨부 원고 제3.3절과 표 1의 공개된 반올림 수치이다. 원래 예측 벡터, 원본 소스 코드 및 체크포인트는 첨부되지 않았다. 여기서는 두 모델이 고유한 128차원 회귀 목표를 썼던 MSE의 단위 차이를 검산한다.

- E가 좌표평균 MSE이고 V가 목표분포의 총분산이면, 테스트 평균으로 예측하는 상수 기준의 좌표평균 MSE는 V/d이다(경험분산은 분모 N을 사용). 따라서 R=dE/V이다. 표의 자릿수를 전제로, R은 Token ID 약 1.520, 문자 인코더 약 1.053으로 복원된다.
- 같은 d에서 E₁/E₂=(V₁/V₂)·(R₁/R₂)이다. 수정 전 원고의 LAMBADA 수치를 대입하면 32.527≈22.530×1.444이다. 이 항등식은 집계값의 분해이며 개별 데이터나 원래 학습 실행을 검증하지 않는다.
- 검증 시에만 마스크를 적용한 MSE 상승 배율은 1.41/0.126≈11.19, 0.062/0.00079≈78.48이다. 학습과 평가를 모두 인과 조건으로 수행한 모델의 성능은 이 수치에서 추정할 수 없다.

## 구조적 검산

```bash
python architecture.py --out rerun
```

원고 제2절의 구성만으로 파라미터 수, 문자 슬롯당 곱셈-누산 연산 수 및 수용영역을 검산한다. 결과는 `architecture_components.csv`와 `architecture.json`이다.

- 기준 모델의 토큰 입력 테이블은 20,000×128=2,560,000개이다. 두 모델이 공유하는 구조는 Transformer 본체 1,586,176개(층당 198,272개), 출력층 2,580,000개(편향 포함)이다. 원고에서 비교한 비공유 기준 모델은 총 6,726,176개, 문자 모델은 총 4,230,145개이며 문자 입력 모듈의 파라미터는 63,969개이다.
- 같은 크기의 Token ID 모델에서 입력 테이블과 출력 가중치를 공유하는 경우, 총수는 4,166,176개이다. 이 가상 기준을 분모로 하면 문자 모델의 총 파라미터가 63,969개(1.5354%) 더 많다. 공유 기준의 성능은 학습·측정하지 않았다.
- 임베딩 조회 뒤 길이 128의 모든 슬롯에서 밀집 합성곱과 마지막 선형 사영을 수행한다고 가정한다. 슬롯당 MAC 수는 128×64+64×32+32×16+2(3+1)(64²+32²+16²)+16=53,776이고, 단어당 6,883,328 MAC이다. 1 MAC은 곱셈 한 번과 누산 한 번이다. 조회, 편향, GELU, 정규화, 잔차 덧셈 및 Transformer/출력층 연산은 산정 범위 밖이다. 실행시간, 메모리 사용량이나 최적화된 연산의 측정값은 이 계산으로 얻을 수 없다.
- 세 단계 각각에 커널 크기 3인 합성곱을 한 번 포함한 잔차 블록이 두 개 있다. 스트라이드와 dilation이 모두 1이고 채널 축으로 LayerNorm을 적용하는 경우, 내부 위치의 최대 이론적 문자 수용영역은 1+3×2×(3−1)=13이다. 경계의 유효 입력 문자 수는 패딩에 따라 줄어든다.
